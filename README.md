## 🧭 How I work

1. **Read the guidelines first** — every project has its own schema and edge cases, so I go through them fully before annotating anything
2. **Annotate** — boxes, masks, labels, transcripts or tags, applied consistently, following the schema provided
3. **Review for quality** — a second pass over my own batches to catch mislabels or inconsistent boundaries
4. **Deliver & flag edge cases** — output in the requested format, on time, with a note on anything ambiguous
